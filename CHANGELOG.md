# Changelog

All notable changes to **Sympony** will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **Windows installer:** The installer and the uninstaller show Sympony's icon rather than NSIS's default one, and `release/build.sh` builds on a PC where `python3` is only the Microsoft Store's alias (it takes the first Python that runs).
- **Launch at login (Windows):** Settings → General → Launch at login, and the onboarding step that turns it on, only saved the setting: nothing started Sympony at login. On Windows it now lists Sympony where Task Manager → Startup apps and Settings → Apps → Startup read it (`HKCU\...\CurrentVersion\Run\Sympony`, the quoted path), takes it off when turned off, and follows those pages: turned off or on there, the setting says so when Sympony starts or Settings opens, and turning it on in Sympony clears Task Manager's "disabled" mark. An install that already had it on is listed at its next start; a debug build never lists itself; uninstalling removes the entry. `platform::os::startup` keeps the list (macOS: not yet, #57).
- **Floating video and YouTube's errors:** the floating video said “YouTube doesn’t allow this video to play here” for any error the YouTube player reported and kept saying it until another video came, so a passing failure read as a ban. It now says so only when the video may not play outside YouTube (101, 150, 153), says the video isn’t available for 100, and for any other error loads the video again once after 3 s, saying “YouTube couldn’t play this video here” only if that fails too. The notch and the floating video log the player’s code with the video id (never its title). `NotchKit.ytErrorKind` holds the rule for both (#59).

## [0.2.0] - 2026-11-24

### Added
- **Official Windows 10/11 x64 Support & Full Desktop Parity:** Native Win32/WinRT backend (`crates/platform/src/windows`) with NSIS desktop installer (`Sympony_0.2.0_x64-setup.exe`), bundled `sherpa-onnx` runtime DLLs, Notch + Fullscreen DWM Cloak + AppBar strip (`Keep windows below Sympony`), Music/GSMTC & YouTube Video Mode, Control Center (Audio, Wi-Fi, Bluetooth, Brightness, Focus/DND, Color Picker), System/Battery/Session stats, Location, Clipboard History & Recycle Bin, Windows Notifications (`wpndatabase.db`), Calendar & Radio, Voice dictation keys & RAM tiering, and Pony Eyes & Hands via UI Automation, SendInput, and in-memory Vision/OCR. (Note: Windows installer is not yet Authenticode-signed, so SmartScreen may prompt "More info → Run anyway".)
- **Dual-Channel In-App Auto-Updater (macOS & Windows):** Automatic update checks across Stable (`latest.json`) and Beta (`beta-channel/latest.json`) channels with cryptographic signature verification, live download progress, non-downgrade channel switching, and Apple Developer ID signed + notarized macOS builds.
- **Feed & RSS Module + Fast Streaming Pony Summaries:** Cross-platform OLED Feed & RSS reader (Hacker News, GitHub Trending with owner avatars, Google News Indonesia + custom topics, Indonesian news portals, global presets, and custom RSS/Atom feeds) with 3 Module Styling Library layouts, SSRF-safe cached favicons, article thumbnails, opt-in background batch auto-summary, live SSE streaming summaries (`feed:sumDelta`), and Claude Code Haiku fast-task pinning.
- **Google Calendar & Google Tasks OAuth Sync:** Bidirectional Google Calendar & Google Tasks OAuth integration directly from the Calendar & Todo modules and Pony chat, paired with a Pony tool-execution safety guard that prevents unexecuted calendar/task mutation claims.
- **Floating Pony Chat Window & Liquid Smoked Crystal Glass:** Detachable, resizable, always-on-top Floating Pony Chat (`pony-chat`) sharing live Markdown/streaming/tool history with the notch across macOS and Windows, plus upgraded Liquid Glass styling, Notch color themes, and 18 Module Styling Library layouts across 3 style packs (Bento Studio, Compact OLED, Minimal Focus).
- **Full Auto UI Mode, Live Voice Steering & Maximized Claude Code Engine:** Quick `Auto UI` composer toggle with zero-token `screen_watch` passive waiting, 3-layer Voice + Auto UI combo (`Auto UI` / `Steer` pill badges, mid-run steering, instant voice stop commands), Active-UI-First Paseo & deep Electron AX/UIA reading (`depth 96` + Head/Middle/Tail truncation), and full Claude Code `stream-json` parity (live WebSearch/WebFetch chips, Commands & files, multimodal attachments).
- **Floating YouTube Video (Picture-in-Picture) & Dismissible Settings `New` Badges:** Pop-out always-on-top muted YouTube video window synchronized within `±0.1 s` to the browser tab (`ytFloat`), plus dismissible `New` (`Baru`) badges across Settings Sidebar, Modules, and new rows.

### Changed
- **Display-Adaptive Notch Sizing & Minimalist Profiles:** Automatically adapts closed & expanded notch dimensions to screen geometry (`notchSizeMode: "auto"`) while preserving explicit compact/minimal user configs, slimmer 13-inch MacBook camera-notch wings, and YouTube seek moved to `Shift + ←/→` so plain `←/→` slides notch modules.

### Fixed
- **Horizontal Trackpad / Wheel Double-Scroll (`#62`):** Momentum-safe `NotchKit.createWheelPager` locks out full macOS/Windows trackpad inertial glide tails, ignores diagonal vertical scroll wobbles, and respects `e.defaultPrevented` from inner sliders/controls.
- **Claude Code AI Usage Auto-Refresh & Keychain Reliability (`#61`):** Automatically refreshes expired/401/Keychain-denied Claude Code OAuth via zero-LLM-token `claude -p /usage`, decodes hex Keychain output, supports `CLAUDE_CONFIG_DIR` hashed Keychain entries, prevents stale `.credentials.json` from masking Keychain denials, falls back to CLI usage output, and restores macOS `"on this Mac"` copy.
- **Pony Peek Below Closed Notch (`#60`):** Decoupled clickable `peekHit` from `notch:hover` (`openOnHover`) and upgraded `#ponyPeek` with `shadow: false`, notch-rim `grip` paws, hover/`done` `wave`, and click-through flicker fix.
- **Voice Model Download UI Glitch (`#58`) & Closed-Notch 1 Hz Flicker:** Sequential download queue, concurrency guard, monotonic progress events, catalog size fallback, and stable `closedStateKey` rendering on non-camera Macs.
- **macOS Gatekeeper & Windows WebView2 Stability:** Notarizes and staples `Sympony.app` before `.dmg` packing, fixes Windows Settings/Onboarding WebView2 deadlocks (`later_on_main_thread`), cloaks Windows notch via `DWMWA_CLOAK`, and preserves Windows MCP environment variables & `HOME` resolution.

- **Windows CI HTTP Test Stability:** Drained request body and sent graceful write-shutdown in `crates/services/tests/http.rs` so loopback redirect tests never hit Windows TCP `RST` (`os error 10053`).

- **3-Layer Voice + Auto UI Integration & Live Voice Steering:** Added a live `Auto UI` badge (and `Steer` badge while a Pony run is active) on the Voice listening pill, voice-accessible `set_auto_ui` toggle (*"nyalakan/matikan auto UI"*), natural per-turn speech overrides (*"tunggu sampai selesai"*, *"otomatis"*, *"tanya dulu"*), a 3-way `Voice Auto UI` preference in *Settings → Voice*, live mid-run Voice Agent Steering (auto-routing Voice to Pony even when Hands focused a text box, waking `screen_watch` within 200 ms, pausing between `screen_do` steps, syncing Notch & Floating Chat without covering the screen), and instant mid-run voice stop commands (*"stop"*, *"berhenti"*, *"batalkan"*, *"cancel"*) (`#22`).
- **Public Roadmap & Agent Collaboration Guide:** Added [AGENTS.md](AGENTS.md), updated issue templates, and linked the public GitHub Project board (**Sympony Roadmap**) in [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).
- **Windows port, System:** On Windows, the System tab shows the CPU (its name, how busy, over time), memory (in use as Task Manager counts it, the kernel's non-paged part as "wired"; Windows has no public reading of compressed memory), the system drive (named as Explorer does, e.g. "Local Disk (C:)") and the network's speeds over the real adapters; the battery ring and its HUD read the battery, charging and battery saver; and the session readings work: idle time, the lock screen, a fullscreen app in front (for the clock's chime and the health reminders), Caps Lock and the keyboard language for their HUDs, and the windows on screen for onboarding. `platform::windows::readings` holds the System tab's; `cargo run -p platform --example stats` measures them over a second (`#45`).
- **Windows: Sympony makes way for a fullscreen app.** With Settings → General → Hide when an app is fullscreen (on by default), a game, a video or a presentation filling Sympony's display sends it up out of sight (it slides away, then cloaks via DWM; the mouse goes through) and it comes back when that app goes. With Settings → HUD → Show over fullscreen apps, a HUD (volume, brightness, Caps Lock…) still comes in for its moment meanwhile, alone, and goes again. `platform::os::window::foreground_state` tells what the app in front does on Sympony's display; `wm.rs` moves it. A maximised window doesn't tuck the notch away: it stays as it is (Keep windows below Sympony keeps it off windows instead) (`#46`).
- **Windows: Keep windows below Sympony.** Settings → General → Keep windows below Sympony now reserves a strip as tall as the notch across the top of its display, as the taskbar reserves its own (an app bar, `platform::windows::appbar`), so maximised windows start below Sympony and it never covers their tabs or title bars. The strip is black under the notch, so the two read as one bar; it isn't used while Auto-hide is on, follows Sympony to another display, and gives its space back when turned off or when Sympony quits. Its frosted and app-coloured looks (`reserveBlur`, `reserveMatch`) aren't drawn yet (`#47`).
- **Windows port, Location:** On Windows, Detect my location (Weather, Prayer Times) and Use my current location find where the PC is through Windows' location service (`Windows.Devices.Geolocation`), as Settings → Privacy & security → Location allows it: Location services, apps, desktop apps, and Sympony's own answer where Windows asks each desktop app (Windows' prompt gets a minute). When it's off or refused, Settings says so in Windows' words, with a button to that page. The place's name (city, province, country, in English as the city search names them) comes from OpenStreetMap (Nominatim), sent the position rounded to about 100 m, since Windows has no reverse geocoding for desktop apps; its time zone from Open-Meteo (to about 1 km), or the PC's when that can't be reached. A permission's page in onboarding opens Windows' own (location, calendars, microphone). `cargo run -p platform --example location` tries it (`#48`).
- **Windows port, Clipboard & apps:** On Windows, the clipboard history keeps what's copied: text, and pictures as PNG (the copying app's own PNG, or any other picture Windows hands over as a bitmap); what the app marks private (password managers, as Windows' own clipboard history skips it) and files copied in File Explorer aren't kept, and a picture goes back on the clipboard as PNG and as a bitmap. Sympony now sees the apps: the one in front (Screen Time counts it under its program's name as Task Manager shows it, a Store app as itself rather than its frame), the ones open (the per-app auto-hide and gap lists), an app's icon and name (a program, or a Start menu app as the media controls name it, so Music shows the playing app's icon), the keyboard given back to the app that had it after typing in the notch, and an agent's terminal brought forward. Files show Explorer's icons, and the Shelf's delete moves them to the Recycle Bin. `platform::windows::image` turns bitmaps into PNG and back (with the `png` crate Tauri already brings); `cargo run -p platform --example apps` tries it (`#49`).
- **Windows port, Notifications:** On Windows, Show Windows notifications in Sympony works: Windows' notification database (`wpndatabase.db`, this account's own, opened read-only beside Windows' service) is read every second, and each new toast shows under the notch with its app's name and icon and goes into the history. Its texts come from the toast's XML (`services::notif::parse_toast`: the title, the body a line each, a browser's site as the subtitle). A click activates its app as Windows' own click does: a Store app with the toast's launch argument, a desktop app through the toast activator it registered (browsers, chat apps), else the app opens. Follow Do not disturb holds them back while it's on: into the history marked as held, a quiet pop-up with Quiet pop-ups during Do not disturb, and how many when it ends; the history page now reads Do not disturb's state (`notif.dnd` says it's known, and how strict). Don't show them twice turns off Windows' own pop-up for each app Sympony shows (its Show notification banners) and gives each back as it was when that or the notifications are turned off, or Sympony quits (kept in `notif-banners.json` against a crash). Send a test posts a toast as Sympony, registered with its name and icon under `AppUserModelId`. Not yet: the toasts' pictures, the Telegram hint (`#50`).
- **Windows port, Calendar & Radio:** On Windows, the calendar also shows the computer's own calendars, read from Windows' appointment store (Windows' Calendar app and the accounts added to Windows), as macOS's are: each event's time, length, all-day, place, notes, link, organizer, its calendar's name and colour, a repeating event as each of its times, and cancelled meetings left out. Windows asks a desktop app nothing here (Settings → Privacy & security → Calendar decides); calendar links and Sympony's own events work as before. The radio plays on Windows through Windows' media player (MP3, AAC, HLS), kept out of the system media controls so Music doesn't read Sympony's own player back as another app; a station that can't be played says why. `cargo run -p platform --example calendar` and `--example radio -- <url>` try them (`#51`).
- **Windows port, Voice:** On Windows, the dictation and command keys work: a keyboard hook that only listens feeds the same hold / double-tap / Esc logic as macOS. The keys keep their settings and Settings names them as Windows does (Right Ctrl, Right or Left Alt, Right Shift, Right Windows key; Fn, which Windows never sees, isn't offered); held alone, Alt or the Windows key no longer opens a menu or Start when let go (a mask key, as AutoHotkey does). The text goes where the user types as on macOS: on the clipboard for a moment (marked so clipboard histories skip it), Ctrl+V, then what was on the clipboard back; an app running as administrator, which Windows keeps a normal app's keystrokes from, gets it on the clipboard instead. The microphone's permission is read from Settings → Privacy & security → Microphone (and asked for where Windows asks desktop apps). Windows has no Accessibility permission, so Voice's setup no longer waits for one there; the Voice page speaks of this PC (`#52`).
- **Windows port, Pony's Eyes & Hands:** On Windows, Eyes reads the window you're looking at through UI Automation (native apps, and web pages in Chromium browsers, Electron and WebView2 apps), as the same elements macOS's Accessibility gives: each control type under macOS's role name (a button, a link, a text field, a heading, a page's text…), so Eyes lists and Hands acts on both alike; password fields' values are never read, and parts of a long page far out of view are skipped. Hands presses, toggles, selects, sets values and picks a popup's or a menu bar's item through the element's own patterns, and otherwise types (any keyboard layout), presses keys (macOS's key names: ⌘ and Ctrl both press Ctrl), clicks, double- and right-clicks, drags and scrolls with real input at the element's place; an app is brought forward as Windows allows a background app to. Windows asks no permission for any of it, so Settings no longer asks for Accessibility or Screen Recording there (`#23`).
- **Windows port, the computer's name:** On Windows, Settings and the notch say "this PC" where they said "this Mac" (Pony Assistant and its brain, skills and MCP servers, Integrations, Media, Notifications, Voice, the module cards, scheduled briefs, Translate and AI Chat), Pony's skills open in File Explorer rather than Finder, the chat's hints show Ctrl where a Mac shows ⌘, YouTube video mode names the browsers it reads on Windows (Chrome, Edge, Brave and Vivaldi), and the first-run permissions step says Windows asks nothing there. Notifications that can't be read say so about Windows' notifications (`#53`).
- **Windows port, Eyes' pictures:** On Windows, Eyes can also look at a picture of the window, for what has no names to read (canvases, charts, pictures of text, icons without labels): the window draws itself into the picture, also when other windows cover it, and it goes to the AI as a JPEG, or Windows' own text recognition reads the text in it on this PC, in the languages set up in Windows, so Hands can click it. The picture stays in memory and is never saved. Windows asks no Screen Recording permission for it (`#23`).

## [0.2.0-beta.4] - 2026-11-23

### Added
- **Official Windows x64 Release & Dual-OS Auto-Updater:** Sympony now ships official signed Windows NSIS installers (`Sympony_<v>_x64-setup.exe`) alongside macOS (`darwin-aarch64`) in a unified multi-platform `latest.json` (`darwin-aarch64` + `windows-x86_64`). Both macOS and Windows receive independent Stable and Beta update notifications matched to their OS binary.
- **Floating Pony Chat Window:** Detach Pony into a resizable, draggable, optional always-on-top floating companion window (`pony-chat`) that shares live chat history, streaming responses, Markdown, tool steps, approval cards, and Glass/OLED looks across both macOS and Windows (WebView2 deadlock-safe), with one-click dock-to-notch and tray menu toggle.
- **Liquid Smoked Crystal Glass Style:** Upgraded the `Glass` notch look (`data-look="glass"`) with multi-layer translucent depth, a 1 px directional specular bevel (`::before`), and seamless concave shoulder transitions.
- **Copy User Chat Messages & Q&A Answers:** Added hover Copy buttons on user messages and interactive Q&A answer summaries in Pony Chat alongside assistant message copy.
- **Windows port, phase 1 (builds and tests):** The Rust workspace now builds and its tests run on Windows. `crates/platform` has a `windows` backend with the same modules and signatures as `macos` (stand-ins that report "not available" for now), both reachable as `platform::os`; a new `platform::process` (own process group, kill the group, is a pid alive, parent pid) for Unix and Windows; and a `Rust (Windows)` CI job. On Windows, `crates/voice` links sherpa-onnx as DLLs (its static libraries use the static CRT, which MSVC won't mix with Rust's), and Pony's command and file tools refuse until their secret-place guards handle `cmd` syntax and Windows paths.
- **Windows port, phase 2 (the notch):** On Windows the notch now sits centred on its display, stays above other windows and opens on hover with its modules. `platform::windows` reads the displays (per-monitor DPI, in the same points as macOS), the pointer and its buttons, and the taskbar; and sets Sympony's windows topmost, out of Alt+Tab, click-through or in front. With mixed display scales, the displays other than the primary one are placed approximately.
- **Windows port, phase 3 (opening things):** On Windows, links, files and folders open in their app (ShellExecute), "show in folder" selects the file in Explorer, "Open with" starts the chosen program, and the file dialogs (Shelf, Launcher, drop actions, the adhan, backup import) are Explorer's. Both OSes reach this through `platform::os::shell` (`open`, `reveal`, `open_with`) and `platform::os::files::choose`; macOS keeps `open` and its AppleScript dialogs, moved as they were. `open_external` also accepts a Windows Settings page (`ms-settings:…`) and the Wi-Fi list (`ms-availablenetworks:`), which the Windows frontend links to; other Windows schemes stay refused.
- **Windows port, Music:** On Windows, Music shows what plays in any app that reports to the system media controls (Spotify, the browsers, Media Player, VLC, …): title, artist, album, cover, progress, and play/pause, previous/next, seek, shuffle and repeat, sent only to the app shown. `platform::os::media` reads them (GlobalSystemMediaTransportControls) and answers as `media_mac.js` does, so `services::media::from_poll` reads both; it now also passes on which controls the app takes (`canPrev`, `canNext`, `canSeek`). `cargo run -p platform --example media_source` plays two silent made-up songs to try it with.
- **Windows port, YouTube video mode:** On Windows, a YouTube video playing in Chrome, Edge, Brave or Vivaldi plays (muted, in step) in the open notch's Music as on macOS. Its id comes from the address bar of the browser window whose title names the video (`platform::os::browser::addresses`, UI Automation); no other window's address is read. A video in a tab behind another (watched in the floating video while working elsewhere, a playlist moving on) is found too: the tab strip says YouTube plays it in one of the tabs (only that yes or no leaves the reading), and YouTube's search for that exact title from that channel gives the video, once per song (up to 3 tries, 5 s apart, when YouTube answers without results). While it isn't found it's looked for again every 2 s (macOS: 5 s). Firefox isn't read yet.
- **Windows port, Control → Sound:** On Windows, Control's volume slider, mute, the microphone tile and the sound output / input lists work. `platform::os::system` reads and sets the default devices through Core Audio (`audio.rs`); choosing a device makes it the default for every use, as Windows' own Sound settings do (IPolicyConfig, undocumented). A device keeps its number while the list changes. `cargo run -p platform --example sound` lists and sets them.
- **Windows port, Control → quick tiles:** On Windows, Dark mode (Light or Dark for Windows and the apps, as Settings sets it), Keep awake (a power request: the screen stays on and the PC awake until it's turned off or Sympony quits), Lock (as Win+L), Screenshot (the notch closes, then Windows' snip overlay opens, as Win+Shift+S) and the brightness slider (the built-in screen's, through WMI; an external monitor's isn't set, as on macOS) work. A brightness change made with the keys or Windows' slider is picked up as it happens (WMI's brightness events) rather than asked for every 200 ms. Keep awake and opening the screenshot tool moved into `platform::os::system` (`keep_awake`, `screenshot`) for both systems; macOS's `caffeinate` and Screenshot are unchanged. `cargo run -p platform --example control` reads and sets them.
- **Windows port, Control → Wi-Fi, airplane mode, Focus, Color picker:** On Windows, the Wi-Fi tab lists the networks around (a fresh scan, with each one's signal, band and security), marks the saved ones, joins one with its saved profile or a password (an open network with none), and leaves it; Windows' reason is shown when joining fails, and a profile made for a password that didn't work isn't kept (Native Wifi, `wlanapi`). Since Windows 11 24H2 the names need the location allowed for desktop apps; when Windows refuses, the tab explains it as on macOS. The Wi-Fi and Bluetooth switches go through Windows' radio switches (`Windows.Devices.Radios`), and their `radios.set` is now registered (it wasn't on any system). Airplane mode is read (its HUD now shows when it changes, also by a laptop's key) and switched by its tile (Windows' radio manager, undocumented). Focus reads Windows' notification mode and its tile turns Do not disturb on and off (`notif.dnd` / `notif.setDnd`; quiet hours settings, undocumented). The Color picker tile and the `colorPickShortcut` setting open a magnifier over a still of the screens; a click, Enter or Space copies the colour as `colorPickFormat` says (`services::colorpick`) and the notch shows it, Esc or a right-click lets go, the arrow keys move one pixel (ten with Shift). The clipboard takes text on Windows (`files::write_text`). The undocumented COM calls (this, the default sound device) share one helper that names each method's place.
- **Windows port, Control → Bluetooth:** On Windows, the Bluetooth tab lists the paired devices, classic and LE (a device that's both, once), with whether each is connected and what it is (from its class, or an LE device's appearance), and connects or disconnects a headset or speaker as Windows' own Connect does (the Bluetooth audio driver's reconnect / disconnect, `KSPROPSETID_BtAudio`). Windows connects the other devices (a keyboard, a mouse) by itself, and Sympony says so when asked to. `cargo run -p platform --example control -- bt` lists them.
- **Floating video (picture in picture):** the video in Music has a new button that opens it in a small window over every other window, to watch while working: muted and in step with the tab like the notch's (the sound stays the tab's), with play/pause, previous/next and seek going to the tab, Space / ← → / Esc, dragged anywhere and resized at its edges, and opened where it was last time (`ytFloat` in Settings). While it's open the video keeps being looked up with the notch closed. Its controls show while the pointer is over it.

### Fixed
- **Windows: Settings froze Sympony.** Opening Settings from the notch (its gear) or onboarding from Settings left an invisible window and stopped every command, until Sympony was quit: a command that isn't async runs inside a WebView2 callback, `run_on_main_thread` from the main thread runs right there, and WebView2 can't finish a new window from inside its own callback. Both windows are now made from the event loop (`native::later_on_main_thread`).
- **YouTube video mode in step with the tab:** the notch's copy is now kept within about 0.1 s of the tab instead of up to 1.5 s off, and no longer lands half a second ahead after each correction. A small difference is caught up by playing the copy a little faster or slower (1.25×/0.75×) rather than jumping; a large one seeks, aiming ahead by the time a seek took the last time (learned) instead of a fixed 0.5 s. Where the copy is counts the time since it last reported (now every 250 ms), and on Windows a new position from the app (a seek, a stall) reaches the notch at once.
- **Windows:** the Launcher no longer maps Windows items to macOS apps (dropping the rest) and saves that over the user's list: that mapping runs on a Mac only.
- **Windows:** `HOME` is set from `USERPROFILE` at start when missing, so `~/.sympony`, `~/.claude`, Downloads… no longer resolve relative to the folder Sympony was started in.
- **Windows:** stdio MCP servers keep the Windows system variables they need to start at all (`SYSTEMROOT`, `TEMP`, `APPDATA`, `LOCALAPPDATA`, `PATHEXT`, …; still never keys or tokens). `tools/extract_contract.py` and `tools/classify_contract.py` read and write UTF-8 instead of Windows' default code page.
